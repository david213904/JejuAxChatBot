# 02. 백엔드 명세

작성일 2026-11-12 · 상태: 초안 v1 · 먼저 `00_공통_기준.md`를 읽을 것

## 1. 역할
- **AI 중계**: 화면이 비밀 키 없이 AI 설명을 받을 수 있게 서버 쪽에서 호출(키 보호, 호출 한도, 입력 제한).
- **데이터 제공(선택)**: 2단계까지는 `data/*.json` 파일을 화면이 직접 읽으므로 서버 불필요. 데이터 갱신을 서버로 옮기는 것은 6단계.
- **저장(5단계)**: 진단 기록, 피드백, 기타 서술(동의한 경우)을 DB에 저장.

백엔드는 크게 만들지 않습니다. **서버리스 함수 1~2개**(예: Vercel Functions 또는 Supabase Edge Functions)로 시작하고, 역할이 늘어나면 서버로 분리합니다. 화면과 같은 저장소에서 관리합니다.

## 2. 단계별 범위
| 단계 | 백엔드가 하는 일 |
|---|---|
| 0~3 | 없음. 단, API 규격 확정과 가짜 응답(mock) 제공, 환경변수 틀(`.env.example`) 준비 |
| 4 | `POST /api/diagnosis/explain` 구현 (AI 1회 호출) |
| 5 | Supabase 연결, RLS, 피드백·기타 서술·진단 기록 저장, 삭제 요청 처리 |
| 6 | 교육 등록 화면용 API(운영진 검수), 데이터 갱신 |
| 7 | 사용량 모니터링, 보안 점검 |

## 3. 기술 선택 (제안, 팀 합의 필요)
| 항목 | 후보 | 메모 |
|---|---|---|
| 실행 환경 | 서버리스 함수(Vercel/Supabase) 또는 Render의 작은 서버 | 기존에 Render를 다뤄 봄. 무료 서버는 한동안 안 쓰면 첫 응답이 느림 |
| DB·로그인 | Supabase(PostgreSQL + 로그인) | RLS 필수. 서울 리전 선택 가능 |
| AI 모델 | 기본 후보 `claude-haiku-5-5` (설명 문단은 가벼운 모델로 충분), 품질 부족 시 `claude-sonnet-5-5` | AI 호출은 **한 모듈**에 모아 나중에 교체 가능하게 |
| 개발용 DB | SQLite(로컬 테스트용) | 서버 안의 파일은 재배포 때 지워질 수 있어 운영에는 사용 금지 |

## 4. API 상세 (초안)
공통: JSON, UTF-8. 오류는 `{ "error": { "code": "...", "message": "..." } }`.

### 4-1. `POST /api/diagnosis/explain` (4단계)
진단 결과로 AI 설명 문단 **1개**를 만듭니다. 진단 자체는 화면이 규칙으로 계산해 이미 끝낸 상태입니다.

요청
```json
{
  "stuck": "bad",
  "job": "office",
  "level": "2",
  "paid": "no",
  "otherText": "",
  "schemaVersion": 1
}
```
- 허용 값은 `data/taxonomy.json`의 코드값만. 그 외 값은 400.
- `otherText`는 최대 200자. 이름·전화번호·이메일 패턴은 서버에서 가려서(마스킹) 처리하거나 거절.

응답 200
```json
{
  "explanation": "…한 문단 설명…",
  "source": "ai",
  "model": "claude-haiku-5-5"
}
```
- AI 호출 실패, 시간 초과(제안: 15초), 하루 한도 초과일 때는 오류가 아니라 `{ "explanation": null, "source": "fallback" }`로 응답 → 화면은 규칙 결과만 표시.
- 응답 문단에는 **데이터에 없는 교육 이름·일정을 지어내지 않도록** 지시. 교육 목록은 화면이 규칙으로 따로 보여 줌(AI에게 교육 정보를 새로 만들게 하지 않음).

오류: 400(잘못된 값), 413(입력 너무 김), 429(호출 한도 초과), 500.

### 4-2. `POST /api/feedback` (5단계)
```json
{ "diagnosisId": "…", "helpful": true, "reason": "recommend_mismatch", "schemaVersion": 1 }
```
`reason`은 정해진 코드 목록(예: ok, recommend_mismatch, info_missing, other) 중 하나. 자유 입력은 받지 않음.

### 4-3. `POST /api/free-text` (5단계, 동의한 경우만)
```json
{ "text": "…", "consent": true, "stuck": "other", "schemaVersion": 1 }
```
- `consent`가 true가 아니면 저장하지 않고 400.
- 저장 전 개인정보 패턴(전화번호, 이메일, 주소 형태) 가림 처리. 계정 식별자와 **분리 저장**(익명 처리).

### 4-4. 진단 기록 (5단계)
로그인한 사용자의 기록은 Supabase에서 화면이 직접 읽고 쓰도록 하고, RLS로 "본인 기록만"을 보장합니다. 필요 시에만 함수로 감쌉니다.
- 재진단은 기록을 **덮어쓰지 않고 쌓음**(날짜, 질문 버전 포함).
- 불러올 때 추천 교육 목록은 **저장하지 않고 접속 때마다 최신 데이터로 다시 계산**.

## 5. AI 호출 규칙
- 호출은 **진단 1회당 최대 1회**. 최대 출력 길이 제한(제안: 300~400 토큰 이내).
- 시스템 지시: 한국어, 한 문단, 존댓말, 규칙 결과(막힌 지점·단계·직군)를 설명하되 새로운 사실·교육·일정을 만들지 않음, 모르면 모른다고 답함.
- 같은 입력(코드 조합)은 **캐시**해서 재호출을 줄임(5단계에서 DB, 그 전에는 메모리 캐시 또는 생략).
- 프롬프트·모델 이름·출력 길이는 설정 파일 한 곳에서 바꿀 수 있게 함.
- 사용량이 늘면: 호출 줄이기(캐시) → 가벼운 모델 → 로컬 모델 전환 순서로 검토(기획서 14절). 이를 위해 AI 호출부를 `ai/` 한 모듈로 분리.

## 6. 보안 체크
| 항목 | 규칙 |
|---|---|
| 비밀 키 | 환경변수로만 보관. 저장소에 올리지 않음. 노출이 의심되면 즉시 폐기 후 재발급 |
| CORS | 허용 도메인 목록(`FRONT_ORIGINS`)만 허용 (로컬 개발 주소 포함) |
| 호출 한도 | IP·사용자별 분당/일일 제한, 전체 하루 상한. 상한 도달 시 `fallback` 응답 |
| 입력 검증 | 코드값 화이트리스트, 길이 제한, 알 수 없는 필드 무시 |
| 프롬프트 주입 | 사용자 서술은 지시가 아니라 **데이터**로만 전달, 시스템 지시를 바꾸지 못하게 구분해서 보냄 |
| 로그 | 키·토큰·서술 원문을 로그에 남기지 않음. 오류 코드와 호출 횟수 위주 |
| Supabase | 모든 표에 RLS 켜기. 서비스 키는 서버에서만, 화면에는 공개용(anon) 키만 |

## 7. DB 초안 (5단계, Supabase/PostgreSQL)
개인정보와 진단 답변은 **표를 나눠** 저장합니다(삭제·유출 대응).

| 표 | 주요 항목 | 접근 규칙(RLS) |
|---|---|---|
| profiles | user_id, 가입일, 동의 버전·시각 | 본인만 읽기·삭제 |
| diagnoses | id, user_id, stuck, job, level, paid, schema_version, ai_text(선택), created_at | 본인만 읽기·쓰기·삭제 |
| feedback | id, diagnosis_id, helpful, reason, created_at | 본인 쓰기, 운영진 읽기(집계) |
| free_texts | id, text(가림 처리본), stuck, schema_version, created_at | 쓰기만 허용, 사용자 식별자 없음, 운영진 읽기 |
| courses(6단계) | 00번 문서 5절 스키마 | 읽기 공개(published), 쓰기 운영진 |

- 보관 기간·파기 방식·동의 문구는 확정 전까지 "미정"으로 두고, **수집 전에 반드시 확정**.
- 로그인 방식은 소셜 로그인(구글·카카오) 우선 검토. 제주AX단에 기존 회원 시스템이 있는지 운영진께 확인 후 연동 여부 결정.
- 무료 요금제는 사용이 없으면 프로젝트가 일시 중지되거나 백업이 제한될 수 있으므로 운영 전에 현재 조건을 확인.

## 8. 환경변수 (`.env.example`에 이름만 적고 값은 비움)
| 이름 | 용도 |
|---|---|
| ANTHROPIC_API_KEY | AI 호출 (서버 전용) |
| AI_MODEL | 사용할 모델 이름 |
| AI_MAX_TOKENS | 출력 길이 제한 |
| DAILY_AI_LIMIT | 하루 전체 호출 상한 |
| FRONT_ORIGINS | 허용할 화면 주소 목록(쉼표 구분) |
| SUPABASE_URL | 5단계 |
| SUPABASE_ANON_KEY | 5단계, 화면에도 전달되는 공개용 |
| SUPABASE_SERVICE_ROLE_KEY | 5단계, **서버 전용** |

## 9. 폴더 제안
```
backend/
├─ api/
│  └─ diagnosis/explain.js    4-1 함수

```

## 10. 테스트·완료 기준 (4단계)
- [ ] 허용되지 않은 코드값·너무 긴 입력은 400/413
- [ ] AI 키를 일부러 틀리게 해도 화면이 `fallback`으로 정상 동작
- [ ] 한도를 낮춰 두고 초과 시 429 또는 `fallback`
- [ ] 허용하지 않은 도메인에서 호출하면 거부
- [ ] 저장소와 응답, 로그 어디에도 키가 없음
- [ ] 로컬에서 키 없이도 mock으로 화면 개발 가능

## 11. 하지 않는 것
- 진단·추천 계산을 AI에게 맡기지 않음(규칙은 화면과 `data/`에서).
- 화면이 AI를 직접 호출하게 하지 않음.
- 동의 없는 서술 저장, 이름·연락처·거주지 수집을 하지 않음.
- 개인 계정 한 곳에만 회원 데이터를 두지 않음(운영 단계에서 팀·제주AX단 소유로 이전 계획 필요).

## 12. 확인할 것 (운영진·팀)
- 제주AX단이 교육 데이터나 API를 제공하는지, 일정이 바뀔 때 반영 방법
- 교육 참가 자격(도민 한정 여부)
- 기존 회원 시스템 유무와 연동 가능성
- AI 키 발급·결제 담당, 월 한도
- 서버·GPU 보유 여부(로컬 모델 전환 검토용)
