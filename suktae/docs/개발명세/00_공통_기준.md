## 1. 서비스 한 줄 정의
제주AX단 홈페이지 방문자 중 **AI를 써 봤지만 막힌 사람**에게, 막힌 지점을 짚고 알맞은 교육을 안내하는 컨설팅형 챗봇.

## 2. 지켜야 할 원칙
| 원칙 | 내용 |
|---|---|
| 2분 진단 | 질문 4~5개, 선택형 위주. 자유 입력은 선택 사항 |
| 규칙이 중심, AI는 보조 | 진단과 추천은 규칙으로 계산(같은 답이면 같은 결과). AI는 설명 문단과 자유 질문에만 사용 |
| AI가 꺼져도 동작 | AI 호출이 실패하거나 한도를 넘으면 규칙 결과만 보여 줌 |
| 정보 부족 표시 | 대상·난이도·선수 조건이 없는 교육은 단정해서 추천하지 않고 "정보 부족"으로 표시 |
| 개인정보 최소화 | 이름·회사·연락처를 받지 않음. 기타 서술은 동의 후 익명으로만 저장 |
| 키는 서버에만 | AI 비밀 키와 서비스 키는 화면 코드·저장소에 넣지 않음 |

## 4. 분류 체계 v1 (가설)
화면의 질문 선택지와 교육 등록 양식이 **같은 코드값**을 씁니다. 코드값은 영문 소문자, 한글 이름은 화면 표시용입니다.

### 4-1. 막힘 유형 (`stuck`)
| 코드 | 이름 |
|---|---|
| bad | 결과가 마음에 안 듦 |
| what | 뭘 시킬지 모름 |
| tool | 도구 선택이 어려움 |
| stop | 쓰다가 끊김 |
| trust | 믿을 수 없음 |
| repeat | 반복 작업을 못 넘어감 |
| secure | 보안·개인정보 걱정 |
| alone | 물어볼 곳이 없음 |
| other | 기타 (직접 쓰기) |

### 4-2. 직군 (`job`)
| 코드 | 이름 |
|---|---|
| office | 사무·행정 |
| shop | 소상공인·자영업 |
| edu | 교육·강의 |
| content | 콘텐츠·디자인 |
| dev | 개발·IT |
| etc | 기타 |

### 4-3. 활용 단계 (`level`)
| 코드 | 이름 |
|---|---|
| 0 | 탐색 (거의 안 써 봄) |
| 1 | 질문 (검색 대용·가끔) |
| 2 | 업무 적용 |
| 3 | 반복 자동화 |
| 4 | 직접 제작 |

### 4-4. 그 밖의 값
| 항목 | 코드 | 비고 |
|---|---|---|
| 유료 구독 (`paid`) | yes / no | 교육의 `needsPaid`와 대응 |
| 진행 방식 (`mode`) | online / offline / hybrid | 교육 데이터에 추가 (제안) |
| 지역 (`region`) | jeju / seoul / national_online | 교육 데이터에 추가 (제안, 지금은 jeju + online) |
| 난이도 (`difficulty`) | beginner / intermediate / advanced | 교육 데이터에 추가 (제안) |

## 5. 교육 데이터 스키마 (`data/courses.json`)
| 필드 | 종류 | 필수 | 설명 |
|---|---|---|---|
| id | 문자열 | ✔ | 고유값(영문) |
| title | 문자열 | ✔ | 교육 이름 |
| org | 문자열 | ✔ | 주관 기관 |
| mode | 코드 | ✔ | online / offline / hybrid |
| region | 코드 | ✔ | 4-4 참고 |
| startAt, endAt | 날짜시간(ISO) | 정보 있으면 | 교육 일정 |
| applyOpenAt, applyCloseAt | 날짜시간(ISO) | 정보 있으면 | **접수 기간은 한 교육에 하나로 입력** (시작·마감을 별개 항목으로 올리지 않음) |
| venueName, venueAddress | 문자열 | offline이면 ✔ | 길찾기 링크용 정확한 주소 |
| cost | 문자열/숫자 | 정보 있으면 | 무료/금액 |
| capacity | 숫자 | 선택 | 정원 |
| needsPaid | 불리언 | ✔ | 유료 AI 구독 필요 여부 |
| stuckTags | 코드 배열 | 매칭용 ✔ | 해결하는 막힘 유형 |
| jobTags | 코드 배열 | 매칭용 ✔ | 대상 직군 |
| levelFrom, levelTo | 코드 | 매칭용 ✔ | 대상 활용 단계(시작~도착) |
| prerequisites | 문자열 | 선택 | 선수 지식 |
| outcomes | 문자열 배열 | 매칭용 ✔ | **수업 후 할 수 있는 것** (동사로 끝나게) |
| difficulty | 코드 | 매칭용 ✔ | 4-4 참고 |
| nextCourseIds | 문자열 배열 | 선택 | 다음에 들으면 좋은 교육 |
| link | URL | ✔ | 신청 또는 상세 페이지 |
| source | 문자열 | ✔ | 정보 출처(예: 제주AX단 행사 일정 페이지) |
| infoLevel | full / thin | ✔ | 매칭용 항목이 비면 thin (정보 부족) |
| status | draft / review / published | ✔ | 검수 상태. published만 추천 |
| updatedAt | 날짜 | ✔ | 최종 수정일 |
| schemaVersion | 숫자 | ✔ | 스키마·분류 체계 버전 |

규칙
- 매칭용 항목(✔)이 하나라도 비면 `infoLevel = thin`, 추천 이유에 "정보 부족" 문구를 붙이고 단정 추천하지 않음.
- 접수 마감이 지난 교육은 추천 목록에서 제외(화면과 서버 모두에서 계산).
- 현재 샘플의 교육 4건(memo, design, job, kakao)은 `data/courses.json`에 이 스키마로 옮겨 두었고, 매칭용 항목(막힘 태그, 대상 단계, 수업 후 할 수 있는 것, 난이도)이 확인되지 않아 **4건 모두 thin**입니다. (`widget.js`는 memo만 full로 표시하므로, 위젯과 데이터를 연결할 때 맞춥니다.)
- 접수 마감이 지난 교육(예: memo는 11/11 마감)은 추천에서 제외되므로 시연용 데이터는 최신 일정으로 갱신해야 합니다.
- 외부 기관 교육은 운영진이 대신 입력하거나 thin으로 둠.

## 6. 진단 흐름과 규칙 (현재 샘플 기준)
1. 막힌 지점(`stuck`) → 2. 직군(`job`) → 3. 활용 단계(`level`) → 4. 유료 구독(`paid`) → 결과 카드
- `stuck = other`이면 자유 서술 1줄(선택, 이름·연락처 쓰지 않도록 안내).
- 결과 카드: 막힌 지점·원인·활용 방법·오늘 해 볼 첫 실습·다음 배울 순서·연결 교육(최대 3개)·추천 이유.
- 추천 규칙(샘플): 직군 태그 일치 우선, 직군이 edu/etc이면 느슨하게 포함, 유료 필요 교육은 `paid = no`이면 "조건 불일치" 표시 후 뒤로 정렬, 단계 0이면 입문 안내 문구.
- 이 규칙은 인터뷰 후 바뀝니다. 규칙과 문구는 코드가 아니라 `data/` 파일에서 읽도록 분리합니다.

## 7. 공용 API 약속 (초안)
상세 요청·응답은 `02_백엔드_명세.md`에 있습니다. 화면은 아래 주소만 압니다.

| 단계 | 방식·주소 | 설명 |
|---|---|---|
| 2단계 | (파일) `data/taxonomy.json`, `data/courses.json` | 서버 없이 화면이 직접 읽음 |
| 4단계 | `POST /api/diagnosis/explain` | 진단 결과로 AI 설명 문단 1개 생성 |
| 5단계 | `POST /api/feedback` | 도움이 됐나요 피드백 저장 |
| 5단계 | `POST /api/free-text` | 기타 서술 저장(동의한 경우만) |
| 5단계 | 로그인·저장 (Supabase) | 진단 기록, 재진단 |

서버가 없을 때는 같은 형식의 **가짜 응답(mock)**으로 화면을 먼저 개발합니다.

## 8. 협업 규칙
- 브랜치: `feature/front-...`, `feature/back-...`, `feature/data-...`. main에 직접 올리지 않고 상대가 한 번 보고 병합.
- 하루 한 번 이상 최신 main을 받아 작업. 브랜치는 짧게.
- `data/`와 이 문서를 바꾸는 사람은 **작업 전에 알리고**, 바꾼 뒤 변경 기록에 적음.
- 코드·데이터 파일명은 영문, 파일은 UTF-8, 줄바꿈 방식 통일.
- `.env`는 올리지 않고 `.env.example`에 이름만 적음.
- AI 도구에 작업을 맡길 때도 **담당 폴더만** 수정하도록 지시.
- **GitHub에 올리기 전에는 폴더 이름과 올릴 범위를 확인하고 분명한 동의를 받음.** 협업 저장소는 `david213904/JejuAxChatBot`.
