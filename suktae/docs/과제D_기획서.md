# 과제 D 기획서: 제주AX단 AI 활용 진단·학습 안내 서비스

> 상태: 초안. `(가정)` 표시는 아직 확인되지 않은 내용입니다.
> 홈페이지 정보 기준일: 2026-11-11 (https://jejuaxdan.com/, 이용 허락 받음)

## 1. 과제 이해

| 항목 | 내용 |
|---|---|
| 문제 | 회원 상당수가 자기 AI 수준도, 무엇을 배워 어디에 쓸지도 모른다. 직업과 업무가 제각각이라 강의 시간에 한 명씩 안내하기 어렵다. |
| 과제 | 하는 일과 원하는 결과를 말하면 AI 활용 단계를 진단하고, 도구·방법·배울 순서·첫 실습을 안내하는 서비스를 만든다. 제주 회원의 실제 업무 사례로 시연하고, 강의·실습으로 잇는 방법까지 발표한다. |
| 평가 1 | 막히는 지점과 단계를 **실제 인터뷰**로 찾았는가 |
| 평가 2 | 하는 일과 수준에 맞는 **도구·방법·학습 순서**를 정확히 안내하는가 |
| 평가 3 | 제주AX단 **강의와 커뮤니티에서 바로 쓸 수 있는가** |

## 2. 한 줄 정의

회원이 "내가 하는 일"과 "원하는 결과"를 말하면, 현재 AI 활용 단계를 진단하고 **제주AX단 교육과 연결된 맞춤 학습 경로**를 안내하는 서비스.

## 2-1. 대상과 서비스 관점 (가정)

- **대상**: 제주AX단 홈페이지를 방문한 사람.
- **전제 (가정)**: 방문자는 AI를 한 번쯤 써 봤고, 쓰다가 막혀서 도움을 찾으러 온 사람이다.
- **서비스 관점**: 수준을 평가하는 테스트가 아니라, **막힌 지점을 짚고 다음 행동을 처방하는 컨설팅**.
- **검증 필요**: 방문자 중에는 AI를 거의 안 써 본 사람이나 단순 구경 온 사람도 있을 수 있다. 이 전제가 맞는지는 회원 인터뷰에서 확인하고, 다르면 입문 안내 경로를 별도로 둔다.

## 3. 홈페이지 분석 (활용할 자산)

- 소개: 제주에서 AI를 함께 배우고 업무에 적용하는 교육·업무 자동화 커뮤니티. 슬로건 "배움에서 실행으로". 운영은 제주의빛.
- 학습 흐름이 이미 3단계로 정의돼 있음: ① 관심과 경험에 맞는 교육 선택 → ② 해결할 반복 업무 정리·준비물 확인 → ③ 실습 후 내 일에 작게 적용.
- 교육은 분야 태그(예: 문서·업무)와 형식(3시간 입문, 하루 워크숍, 4시간 실습)으로 구분됨.
- 현재 모집 교육: 11월 12일 "쌓아만 둔 메모, 다시 꺼내 쓰기"(무료, 정원 15명). 일부 교육은 Claude Code/Codex 유료 구독자 대상.
- 지난 교육: Codex 업무 자동화, 바이브코딩 입문, 홈페이지 제작 등 (유료 3~7만 원).
- 커뮤니티 채널: 카카오 오픈채팅, 로드맵, 내 신청, AI 위키.
- 행사 일정 페이지(/events): 날짜별 달력과 일정 목록이 있음. 2026-11-11 화면 기준 11월 한 달에 날짜별로 1~4개씩 일정이 등록돼 있고, 11일에는 3건(제주AX단 무료 3시간 실습, 한라대 실습, 제주경제통상진흥원 디자인 아카데미 교육생 모집 공고)이 보임. 제주AX단 외 기관 교육·공고도 함께 올라옴.
- 한계: 커뮤니티 회원 자격이 명시돼 있지 않음. 기존 문구("행사 일정 목록이 비어 있음", "추천 가능한 교육 종류가 적다")는 첫 화면만 보고 쓴 것이라 삭제함. 일정 페이지의 전체 목록 확인 후 추천 가능한 교육 수를 다시 판단할 것.

**시사점**: 추천할 교육 콘텐츠는 적은 편이므로, 서비스는 "교육 추천"만이 아니라 **도구·방법·첫 실습(AI 위키, 자체 실습 과제)까지 포함한 학습 경로**를 제공해야 한다. 홈페이지가 이미 정의한 3단계 흐름을 그대로 서비스의 뼈대로 쓰면 자연스럽게 이어진다.

## 4. 사용자(페르소나) 가설

인터뷰로 검증할 가설입니다.

| 유형 | 예시 | 막히는 지점(가설) |
|---|---|---|
| 입문 | AI를 몇 번 써 봤지만 결과가 마음에 안 들어 멈춘 소상공인, 직장인 | 무엇을 물어야 할지 모름, 결과를 믿어도 되는지 모름 |
| 정체 | ChatGPT는 쓰지만 업무에 못 붙이는 사람 | 쓰는 단계에서 반복 업무 자동화로 못 넘어감 |
| 심화 | 유료 도구 사용자, 자동화·코딩 도구 관심 | 도구가 많아 선택이 어렵고 어디에 쓸지 모호함 |

## 5. AI 활용 단계 정의 (진단 기준안)

| 단계 | 이름 | 상태 |
|---|---|---|
| 0 | 탐색 | AI를 써 봤지만 검색 대용이거나 가끔만 사용 (써 본 적 없는 경우는 입문 안내로 연결) |
| 1 | 질문 | 일상적 질문·글쓰기에 사용하지만 업무엔 연결 못 함 |
| 2 | 업무 적용 | 문서·정리 등 내 업무 일부에 프롬프트로 사용 |
| 3 | 반복 자동화 | 반복 업무를 도구나 워크플로로 묶어 사용 |
| 4 | 직접 제작 | 코딩 도구 등으로 내 업무용 도구를 직접 만듦 |

> (가정) 5단계는 초안이다. 인터뷰 결과에 따라 합치거나 조정한다.

## 6. 서비스 흐름

컨설팅 순서(막힘 듣기 → 진단 → 처방 → 이어가기)로 진행한다.

1. **막힌 지점 듣기**: 무엇을 하려 했고 어디서 어떻게 안 됐는지.
2. **입력**: 하는 일, 원하는 결과, 지금까지 써 본 AI 경험, 쓸 수 있는 시간·예산 (질문 4~5개, 2분 이내, 선택형 위주).
3. **진단**: 현재 단계와 막힌 원인(예: 질문 방법, 도구 선택, 업무 정리)을 알려줌.
4. **처방(안내)**: 결과 카드에 아래를 담는다.
   - 추천 도구와 선택 이유
   - 활용 방법
   - 배울 순서(2~3단계)
   - **오늘 해 볼 첫 실습** 1개
   - 연결 교육(제주AX단 교육, AI 위키, 오픈채팅)
5. **이어가기**: 교육 신청 링크, 커뮤니티 질문 방법, 실습 후 후속 점검.

## 7. 진단 질문 초안

> 2분 이내로 맞추기 위해 아래 6개 중 핵심 4~5개만 쓰고, 선택형 위주로 한다. 앞 답에 따라 질문을 건너뛰는 적응형으로 하고, 자유 입력은 선택으로 둔다. 질문 목록은 인터뷰 후 확정하며, 소요 시간은 시연에서 직접 재서 확인한다.

1. AI를 쓰다가 막혔던 순간은? (무엇을 하려 했고 어떻게 안 됐나요)
2. 어떤 일을 하시나요? (직업·업종)
3. 그 일에서 가장 시간을 많이 쓰는 반복 작업은?
4. AI로 이루고 싶은 결과는? (예: 보고서 시간 절반으로)
5. 지금까지 써 본 AI 도구와 사용 빈도는?
6. 유료 도구 구독 여부와 사용 가능한 시간·장소는?

| 단계 | 내용 | 산출물 |
|---|---|---|
| A. 인터뷰 | 제주AX단 회원 5~8명 인터뷰 (직업군을 섞는다) | 인터뷰 기록, 막힘 지점 정리 |
| B. 설계 | 단계 기준·진단 질문 확정, 추천 규칙 작성 | 단계표, 질문지, 추천 규칙표 |
| C. 콘텐츠 정리 | 홈페이지 교육·AI 위키 자료를 추천용 데이터로 정리 | 교육·실습 카탈로그 |
| D. 프로토타입 | 입력→진단→안내 흐름 구현 (구현 방식은 별도 결정) | 시연 가능한 서비스 |
| E. 시연 준비 | 실제 회원 업무 사례 2~3건으로 시연 | 시연 시나리오, 결과 카드 |
| F. 발표 | 강의·커뮤니티 연결 방법까지 포함 | 발표 자료 |

## 9. 인터뷰 계획 (평가 1 대응)

- **대상**: 제주AX단 교육 수강자·오픈채팅 참여자 중 직업이 다른 5~8명. 섭외는 운영진(제주의빛) 협조 요청.
- **방식**: 20~30분, 일대일, 녹음은 동의 후.
- **질문**
  - 지금까지 AI를 써 본 적이 있나요? (전제 확인) 홈페이지는 어떤 계기로 방문했나요?
  - 어떤 일을 하고, AI를 어디에 써 보려 했나요?
  - 써 보다 막힌 순간은 언제였나요?
  - 교육을 고를 때 무엇이 어려웠나요?
  - 강의 후 업무에 바로 못 쓴 이유는 무엇이었나요?
- **정리**: 막힘 지점을 유형별로 묶어 단계 기준과 추천 규칙에 반영.
- **주의**: 개인정보 최소 수집, 인용 시 익명 처리.

## 10. 강의·커뮤니티 연결 방안 (평가 3 대응)

- 강의 첫 시간에 진단 서비스로 **수강생 수준·직업 분포를 미리 파악**해 강사가 활용.
- 진단 결과 카드를 **오픈채팅에 공유하는 형식**으로 만들어 질문 시 맥락을 함께 전달.
- 결과 카드의 "첫 실습"을 강의 전 과제나 강의 후 적용 과제로 사용.
- 교육 신청 페이지와 AI 위키로 바로 이동하는 링크 제공.
- 운영진에게 **막힘 지점 통계**를 제공해 다음 교육 기획에 반영.

- [ ] 홈페이지 자료 활용 범위(허락받은 범위 문서로 확인)

## 14. 사용량이 늘어날 때의 대응안 (확장 계획)

> 이번 과제 범위 밖의 계획이다. 기준 수치는 운영 데이터가 쌓인 뒤 정하며, 지금은 대응 순서만 정해 둔다.

### 14-1. 기본 원칙

- AI는 결과 카드의 설명 문장 생성과 후속 질문에만 쓴다. **진단 판정과 교육 추천은 규칙이 처리**하므로 AI 호출 횟수를 구조적으로 줄인다.
- 진단 1회당 AI 호출은 최대 1회로 한다. 후속 질문은 선택 기능으로 두고 횟수를 제한한다.

### 14-2. 단계별 대응

| 단계 | 상황 | 대응 |
|---|---|---|
| 1. 측정 | 운영 시작 | 호출 횟수·입력/출력 길이·월 비용을 익명 로그로 기록 (개인 입력 내용은 저장하지 않음) |
| 2. 줄이기 | 비용이 부담되기 시작 | 프롬프트와 교육 자료 요약본 줄이기, 반복 자료 캐싱, 답변 길이 제한, 후속 질문 횟수 제한, 같은 결과는 재사용 |
| 3. 모델 조정 | 줄여도 부담 | 더 작고 저렴한 모델로 교체하거나, 단순 응답은 작은 모델·어려운 응답만 큰 모델로 나누는 혼합 운영 |
| 4. 로컬 전환 검토 | 사용량이 크게 늘고 조건이 맞음 | 로컬 LLM 시험 후 품질이 기준 이상일 때 일부 기능부터 전환 |

### 14-3. 로컬 LLM 전환 조건

- **신호**: 월 API 비용이 서버 운영 비용보다 커짐, 개인정보 때문에 외부 전송이 어려움, 호출 제한으로 지연이 반복됨.
- **현재 확인된 자원**: 개발용 PC(RTX 5070, VRAM 약 12GB, RAM 약 31GB)는 중간 크기 모델 시험까지 가능. 교육장 PC 약 30대가 있다는 이야기가 있으나 사양과 사용 가능 여부는 미확인.
- **서비스 운영용 서버는 미확인**: 상시 가동 서버와 GPU, 외부 접속 가능 여부는 운영진 확인 필요.
- **전환 전 시험**: 시연·인터뷰 사례로 평가용 질문 20~30개를 만들고, 상용 모델과 로컬 모델의 한국어 품질, 지시 따르기, 홈페이지 정보만 근거로 답하는지(지어내지 않는지)를 비교한다.

### 14-4. 전환을 쉽게 하는 설계

- AI 호출을 한 모듈에 모아, 상용 API와 로컬 모델을 바꿔 끼울 수 있게 한다.
- 진단 규칙과 교육 데이터(`data/`)는 모델과 분리한다.
- 평가용 질문 세트를 계속 쌓아 모델 교체 시 같은 기준으로 비교한다.

### 14-5. 운영진께 확인할 것

- [ ] 교육장 PC 외에 상시 켜 두는 서버가 있는지, GPU가 있는지
- [ ] 챗봇 서비스를 올려도 되는지, 외부 접속이 가능한지
- [ ] 교육장 PC 사양이 모두 같은지, 수업 없는 시간에 시험용으로 써도 되는지
- [ ] 외부 AI 서비스에 방문자 입력을 보내도 되는지(기관 정책)
